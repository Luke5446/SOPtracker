A line is short when the stock on the code ordered, shared out to the oldest promised date first, does not cover it. The suggestion is the code in the same colour and sleeve length with the most free stock: same size first, then a size up or down. Switch in Sage = amend the order line to the other code (goes on the Switch list). Transfer stock = move the garments onto the ordered code instead, with a Sage write-off and add-stock file (goes on the Stock transfer files tab). Once a line is ticked off as changed in Sage or its transfer is imported it leaves this list and sits in the history on the Switch / Stock transfer tabs. Switches not yet done are cleared by the next publish; done switches and all transfers are kept. Codes not on IT's current list are flagged old code.

Bulk changing sales order lines in Sage 200

Sage 200 Professional has no bulk amend for sales order lines. The sales order import only creates new orders, the item code on an existing line cannot be edited (the line is deleted and re-added), and writing to SOPOrderReturnLine in SQL is unsupported and breaks allocations. That leaves three routes:
  1. Transfer the stock instead of the order (this app's Stock transfer files): write the garments off the alternative code and add them to the ordered code. The order then allocates and despatches unchanged. Best while the customer's portal still sends old codes.
  2. Amend line by line from the Switch in Sage list when the customer should see the new code on the invoice.
  3. Fix it at source: ask Wagamama / the portal to map to the current codes, or set the old codes to inactive in Sage so the import rejects them.
